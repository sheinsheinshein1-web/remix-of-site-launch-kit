# Дизайн-система «Много места»

Этот файл — источник истины для новых и изменяемых интерфейсов проекта. Перед UI-правками сначала нужно найти существующий компонент и использовать его. Новый вариант элемента создаётся только тогда, когда существующий действительно не подходит по смыслу.

## Основной характер

- Минималистичный, плоский и контентный интерфейс. Bento не является базовым стилем и используется только точечно для самостоятельных объектов, состояний и отдельных сервисных сценариев.
- Иерархия строится типографикой, расстояниями и контрастом, а не множеством контейнеров.
- Не добавлять декоративные разделительные линии, тени и серые плашки без функциональной причины.
- Не использовать декоративные полосы между секциями. Границы допустимы только внутри функциональных компонентов: таблиц, полей, FAQ и самостоятельных интерактивных областей.
- Единственное постоянное исключение для навигации — одна тонкая линия между верхним и нижним рядами общего десктопного хедера. Она разделяет два уровня навигации и не переносится в контентные блоки или футер.
- Не ставить над заголовками секций короткие служебные подписи или «eyebrow»-лейблы. Раздел начинается с содержательного заголовка либо сразу с основного контента.
- FAQ — функциональное исключение: тонкие горизонтальные линии отделяют повторяющиеся строки аккордеона. Hover, focus и открытое состояние обозначаются синим текстом и шевроном без серой фоновой плашки. Не превращать FAQ в набор карточек и не переносить этот приём на другие блоки без причины.
- Не дублировать одну информацию в соседних блоках.

## Формы и скругления

- Базовое скругление интерфейсных элементов — `3px` (`rounded-[3px]`).
- Не использовать пилюли (`rounded-full`) для чипов, счётчиков и бейджей.
- Не добавлять отдельный квадратный или круглый фон под шеврон либо иконку, если это не самостоятельная кнопка.

## Цвет и ссылки

- Синий — цвет основного действия, выбранного состояния и hover/focus.
- Обычные текстовые ссылки по умолчанию тёмные, при наведении становятся синими.
- В строке заголовка действие располагается справа: например, `Другие проекты — Все проекты ›`.
- Не использовать синий как постоянный декоративный цвет для большого количества ссылок.

## Чип «Проверено»

- Всегда использовать `src/components/VerifiedBadge.tsx`.
- Только текст `Проверено`, без щита, галочки или другой иконки.
- Компактный прямоугольник со скруглением `3px`, светло-синим фоном и синим текстом.
- Не создавать локальные копии этого чипа в страницах или карточках.

## Иконки и действия

- Использовать Lucide с единым тонким начертанием только для функционально понятных действий.
- Не добавлять декоративные иконки к тексту, если смысл уже понятен без них.
- На фотографии действия «назад», «поделиться» и «избранное» — свободные белые иконки поверх лёгкого тёмного градиента, без видимого контейнера. Область нажатия остаётся не меньше `44×44px`.
- Избранное в активном состоянии обозначается красным сердцем.

## Карточки и плашки

- Карточка получает фон только когда он действительно группирует самостоятельный объект или показывает состояние.
- Не превращать факты, характеристики и контактные данные в набор одинаковых серых плиток.
- В профиле производителя допустимы: один общий блок статистики, компактная плашка владельца профиля, цельные карточки проектов и компактный блок состояния отзывов.
- В профиле производителя оставлять плоскими: заголовок и логотип, описание, характеристики, контакты, навигацию и карту.
- Карточка производителя в проекте компактная: логотип, название, чип `Проверено`, число проектов и шеврон без отдельного фона.
- Счётчик лайков — компактный прямоугольник со скруглением `3px`, не пилюля.

## Адаптивность

- Мобильная версия приоритетна; интерактивная область элемента не меньше `44×44px`.
- Длинные описания и второстепенные характеристики можно сворачивать, но полный текст должен оставаться в DOM и раскрываться явной ссылкой.
- Не скрывать значения ключевых характеристик из-за узкого экрана.
- Хлебные крошки могут быть скрыты визуально на мобильной карточке проекта, если остаются стрелка назад и корректный `BreadcrumbList`.

## Географические списки

- Единственный реестр доступной географии — `src/data/regions.ts`: базовые регионы, города доставки, URL, подписи и связь с каталогом добавляются и удаляются только там.
- Хедер, страница `/regions`, региональные страницы и общий счётчик используют `allRegions`; не создавать локальные массивы городов в компонентах или данных проектов.
- В состоянии выбранного города хранится уникальный `slug`. Для фильтрации проектов используется `cityValue` выбранного региона через `src/lib/geoSelection.ts`.
- Во всех списках городов и регионов первыми всегда идут `Москва`, затем `Санкт-Петербург`.
- После них сохраняется сортировка конкретного списка: по числу проектов, алфавиту или исходному порядку.
- Для сортировки использовать общий модуль `src/lib/geoOrder.ts`, а не локальные исключения в компонентах.

## Проверка перед завершением

1. Сначала сравнить элемент с главной страницей и существующими общими компонентами.
2. Проверить ширины `375`, `768`, `1024` и `1440px`.
3. Убедиться, что нет новых пилюль, декоративных плашек, лишних линий и дублирующей информации.
4. Проверить hover, focus и touch target.
5. Запустить TypeScript, тесты и визуальную проверку изменённого экрана.
