# Заявки производителей и покупателей → Google Таблица

Обработчик записывает заявки с партнёрских лендингов и заявки покупателей на расчёт доставки в Google Таблицу, а также отправляет уведомления на почту. Доступ к таблице и адрес уведомлений не попадают в клиентский код сайта.

## Подключение

1. Создайте Google Таблицу для заявок сайта.
2. В таблице откройте **Расширения → Apps Script**.
3. Скопируйте содержимое `PartnerApplications.gs` в файл `Code.gs`.
4. Откройте **Настройки проекта → Свойства скрипта** и добавьте:
   - `NOTIFICATION_EMAIL` — почта для уведомлений;
   - `ALLOWED_HOSTS` — `многоместа.рф,www.многоместа.рф,xn--80afg0abehb3ak.xn--p1ai,www.xn--80afg0abehb3ak.xn--p1ai,127.0.0.1,localhost`.
5. В редакторе выберите функцию `setupPartnerApplications`, нажмите **Выполнить** и подтвердите доступ. Функция создаст листы «Заявки» и «Заявки покупателей», добавит заголовки и сохранит ID таблицы в свойствах скрипта.
6. Нажмите **Начать развертывание → Новое развертывание → Веб-приложение**:
   - выполнять от имени: **Я**;
   - у кого есть доступ: **Все**.
7. Скопируйте итоговый URL вида `https://script.google.com/macros/s/.../exec`.
8. URL текущего развертывания уже задан в клиенте как резервный. При следующем развертывании замените его в `src/lib/partnerApplication.ts` или переопределите на хостинге переменной окружения:

   `VITE_PARTNER_APPLICATION_URL=https://script.google.com/macros/s/.../exec`

   Для заявок покупателей можно отдельно задать `VITE_PROJECT_QUOTE_APPLICATION_URL`. Если переменная отсутствует, используется тот же адрес, что и для заявок производителей.

9. Пересоберите сайт. После изменений кода Apps Script создавайте новую версию развертывания.

## Листы и столбцы

Лист «Заявки» содержит анкеты производителей: дату, компанию, ИНН, формат сотрудничества, сайт, контактное лицо, телефон, страницу, статус, ответственного и комментарий.

Лист «Заявки покупателей» содержит проект, производителя, регион и адрес доставки, участок, оплату, срок, контакты и выбранные дополнительные проекты. Дополнительный выбор обновляет исходную строку по ID заявки и не создаёт дубль.

Новая заявка получает статус «Новая». Поля «Ответственный» и «Комментарий» заполняются вручную в таблице и сохраняются при обновлении списка дополнительных проектов.
